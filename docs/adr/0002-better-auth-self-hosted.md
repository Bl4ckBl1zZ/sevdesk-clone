# ADR 0002 — Better Auth on self-hosted Convex (P0 spike findings)

- **Status:** accepted · 2026-10-12
- **Context:** 02 §4.2 chooses Better Auth (`better-auth` 1.6.33, `@better-auth/passkey` 1.6.33) inside self-hosted
  Convex via `@convex-dev/better-auth` 0.12.5 in Local Install mode. Research 14 left open whether this works on a
  self-hosted backend, inside `convex-test`, and how the invite-only sign-up gate can be atomic. This records what
  the P0 implementation found and the workarounds it needed.

## What works

| Topic | Finding |
|---|---|
| Local Install | `convex/betterAuth/` (component `betterAuth`) with schema generated by `pnpm auth:schema` (scripts/generate-auth-schema.ts calls the adapter's `createSchema`; `npx auth generate` needs a full options object and network access). 7 tables: `user`, `session`, `account`, `verification`, `passkey`, `twoFactor`, `jwks`. The convex plugin excludes the oidc tables. |
| Self-hosted backend | `convex codegen`, `convex dev --once` and the HTTP routes work against the precompiled backend (scripts/convex-local-backend.sh, ports 3290/3291 in the worktree). `test/integration/auth-gate.test.ts` signs the owner in with an e-mail code, exchanges the session cookie for a Convex JWT (`/api/auth/convex/token`) and calls `api.members.me` with it. |
| convex-test | `t.registerComponent("betterAuth", schema, modules)` plus `t.fetch("/api/auth/…")` runs the whole Better Auth HTTP flow in-process (convex/auth.test.ts). `jose` and `better-auth/crypto` bundle in the default runtime; no `"use node"` needed. |
| Atomic sign-up gate | Component triggers (`authFunctions: internal.auth`, `triggers.user.onCreate`) run **in the same transaction** as the user insert. The trigger re-checks the gate (`createMemberFromSignup`) and consumes the invite; throwing rolls back the user row. This is the authoritative gate; the `databaseHooks.user.create.before` check and the pre-send check are early, user-friendly refusals. |
| Static JWKS | The `JWKS` env holds a Better Auth key document whose private JWK is encrypted with `BETTER_AUTH_SECRET` (`symmetricEncrypt`), generated offline by `pnpm auth:keys better-auth`. No `rotateKeys` call and no `jwks` table writes are needed. |
| Second JWT provider | `auth.config.ts` adds a `customJwt` provider (issuer `https://api.<BASE_DOMAIN>`, audience `rechnungen-server`, ES256, JWKS as a data URI from `SERVER_JWKS`). `src/lib/server-jwt.ts` mints the token in `web`. |

## Workarounds

1. **Gate and throttle live in `hooks.before`, not in `sendVerificationOTP`.** The emailOTP plugin swallows errors
   thrown from `sendVerificationOTP` (it answers 200 to avoid address enumeration). The sign-in gate (403, German
   message, `security.access_denied` audit with a hashed address) and the per-address throttle (429, 5/hour and
   20/day via `@convex-dev/rate-limiter`) therefore run in a `hooks.before` matcher for
   `/email-otp/send-verification-otp`. A failed mail is recorded per request and turned into a 503 in `hooks.after`
   (`auth.otp_mail_failed` audit). Address enumeration is acceptable here: the app is tailnet-only (02 §4.1).
2. **`auth.config.ts` may only reference env vars that are set.** Convex refuses to push when a referenced variable
   is missing, so the config reads only `JWKS`, `SERVER_JWKS` and `BASE_DOMAIN`; all must exist in every deployment.
3. **Auth mail is not in `convex/actions/`.** That folder is reserved for `"use node"` modules; the Cloudflare sender
   uses `fetch` and runs in the default runtime (`convex/lib/authMail.ts`, `convex/authMail.ts`). 02 §9 updated.
4. **Passkey lookups need an index the generator does not emit:** `passkey.by_credentialID` is added in
   `convex/betterAuth/schema.ts` on top of `generatedSchema.ts`.
5. **IP rate limiting is off** (`rateLimit.enabled: false`): every request arrives from the tailnet proxy's address.
6. **Cookie cache is off** so a disabled/expired member loses access with the next request; disabling or expiring a
   member deletes all sessions through the component (`revokeSessions`).
7. **Fail closed:** `createAuthOptions` asserts `BETTER_AUTH_SECRET`, `JWKS`, `OWNER_EMAIL`, `PASSKEY_RP_ID` and
   `SITE_URL` when running inside Convex; the HTTP action throws (500) otherwise.

## Members as the user proxy

Roles, expiry and auditor scope live in our `members` table (keyed by `authUserId`), not in Better Auth's
admin/organization plugins. `convex/functions.ts` resolves the actor from the verified JWT, loads the member, checks
that the session still exists (`session._id` from the JWT, `expiresAt > now`), then applies the permission matrix.

## Open

- Better Auth ≥ 1.7 is blocked by Renovate until the hook behaviour above is re-checked (including workaround 8).

## Resolved

8. **TOTP for e-mail-code sign-ins** (02 §4.2): `totpForEmailCodeSignIns()` widens the matcher of the twoFactor
   plugin's first after-hook to `/sign-in/email-otp`. For a user with TOTP the hook deletes the fresh session, sets
   the two-factor cookie and answers `{ twoFactorRedirect: true }`; `twoFactor.verifyTotp` creates the session. No
   pending-session marker is needed in the wrappers or `requireRole()`. It throws at start-up if the plugin ships
   without after-hooks, so an upgrade cannot silently disable it (convex/auth.test.ts covers the flow).
9. **First-run flag for `/anmelden`**: a Better Auth plugin endpoint `GET /api/auth/rechnungen/first-run` runs the
   internal `signup.firstRun` query. Better Auth's HTTP surface is already public; no wrapper-less public Convex
   function and no admin key in `web` are needed (src/lib/auth-server.ts `isFirstRun()`, fail-safe `false`).
